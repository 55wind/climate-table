## 1. 문서 개요

### 1.1 목적
"밥상 차리기" 탭은 현재 **재료 원가**(집에서 사다 해먹는 비용)만 보여준다.
본 개발에서는 두 가지를 추가한다.

1. **"밖에서 사먹을 때(외식) 금액"**을 재료 원가와 나란히 표시한다.
2. 재료 가격을 **소비자가 실제로 사는 단위(포기·개·망·단·포대)**로 보여준다.

목표는 "이 날씨에 내 장바구니와 외식비가 얼마가 되는가"를 더 직관적으로
체감하게 만드는 것이다.

### 1.2 범위
- 대상: `backend/dishes.py`, `backend/app.py`, `backend/test_api.py`,
  `frontend/app.js`, `frontend/style.css`, `frontend/index.html`(필요 시).
- 비대상: 기존 시뮬레이션 탭·학습 퀴즈 탭(변경 없음), 데이터셋·회귀모델 로직.

### 1.3 용어
| 용어 | 정의 |
|---|---|
| 재료 원가(cost) | 음식 재료를 사서 직접 해먹을 때의 비용. 작물=도매가×분량, 부재료=정가. |
| 외식가(eatout) | 식당에서 사먹을 때의 금액. 음식별 메뉴 기준가 + 기후로 오른 재료비 전가. |
| 구매단위 | 소비자가 실제 사는 단위(배추=포기, 무·사과=개, 양파=망, 시금치=단, 쌀=포대). |
| 평년 기준(baseline) | 극단기상이 없는 BASELINE 기상에서의 가격. 날씨 효과 분리용. |
| 전가 | 재료비 상승분이 외식 메뉴가에 더해지는 것. |

## 2. 배경 및 문제 정의

기존 화면은 밥상 총액을 "재료 원가" 한 가지로만 보여준다. 두 가지 한계가 있다.

- **체감 격차**: 사람들은 재료를 사서 해먹기도 하지만 사먹기도 한다. 외식가를
  함께 보여줘야 "기후플레이션이 외식비까지 올린다"는 메시지가 완성된다.
- **단위 괴리**: 원가를 1인분 분량(예: 배추 0.12kg)으로만 계산하면 금액이
  작아(수백 원) 체감이 약하다. 소비자는 "배추 한 포기 5,400원"으로 가격을
  기억한다. 구매단위 가격을 함께 보여주면 훨씬 와닿는다.

### 3.2 기능 상세

**F1. 외식가 계산**
- 각 음식에 평년 기준 **메뉴가(menu_base)**를 정의한다.
- 외식가 = `menu_base + (재료원가_예측 − 재료원가_평년)`.
- 평년 날씨에서는 외식가 = menu_base. 폭염 등에서는 재료 상승분만큼 가산.
- 식당이 재료비 오른 만큼 천천히 메뉴가를 올리는 현실을 단순화한 모델.

**F2. 총액 2종 표시**
- 결과 패널 최상단에 두 줄(또는 두 칼럼):
  - 재료 원가(집밥): 강조 큰 숫자 + 평년比 %.
  - 사먹을 때(외식): 보조 숫자 + 평년比 %.

**F3. 구매단위 가격**
- 원자재(기후 작물) 분해의 각 막대에 단위가를 함께:
  - 예: `배추 1포기 9,625원 (평년 5,400) · +78%`.
- 단위가 = 도매가(원/kg) × 단위중량(kg). 별도 소매 마진은 적용하지 않는다
  (기존 packPrice 관례 유지, 과대표기 방지).

**F4. 음식별 2종 가격**
- 음식 목록 각 행: `김치찌개  원가 4,400 · 외식 8,249  (+6%)`.

**F5. 데이터 분리 / F6. API 확장** → 5절·6절 참조.

## 7. 가격 계산 로직 (backend/app.py compute_meal)

### 7.1 정의
- 작물 재료비(원가) = `predict(작물, 시나리오, 월) × 분량(kg)`.
- 부재료(고정) = `won` 그대로(예측=평년 동일).
- 음식 원가 cost = Σ(작물 재료비) + Σ(고정 재료비).
- 음식 외식가 eatout_pred = `menu_base + (cost_pred − cost_base)`,
  eatout_base = `menu_base`.
- 단위가 unitPrice = `predict(작물, 시나리오, 월) × UNITS[작물].kg`.
- 변동률 pct = `round((예측 − 평년) / 평년 × 100)`, 평년=0이면 0.

### 7.2 계산 예시 — 김치찌개 (8월, 2024 폭염 프리셋)
재료: 배추 0.12kg · 양파 0.05kg · 무 0.03kg · 돼지고기 2,500 · 두부 900 · 양념 400

| 항목 | 평년 | 폭염 |
|---|---|---|
| 배추 (도매×0.12) | 259원 | 462원 |
| 양파 (×0.05) | 56원 | 66원 |
| 무 (×0.03) | 37원 | 72원 |
| 고정 재료 합 | 3,800원 | 3,800원 |
| **재료 원가(cost)** | **4,151원** | **4,400원** |
| **외식가(eatout)** | **8,000원** | **8,249원**(=8,000+249) |

→ 재료 원가는 +6%, 외식가는 +3% 상승. 폭염이 집밥·외식 모두를 올리지만,
외식가는 메뉴 기준가가 커서 상승률이 완만하다(현실적).

### 7.3 작물 단위가 예시 (8월)
| 작물 | 평년 단위가 | 폭염 단위가 | 변동 |
|---|---|---|---|
| 배추 1포기 | 5,400원 | 9,625원 | +78% |
| 무 1개 | 1,220원 | 2,400원 | +97% |
| 양파 1망 | 1,665원 | 1,980원 | +19% |
| 시금치 1단 | 1,316원 | 1,532원 | +16% |
| 사과 1개 | 999원 | 1,170원 | +17% |
| 쌀 20kg 포대 | 54,000원 | 56,200원 | +4% |

## 8. API 명세

### 8.1 GET /api/dishes
- 각 음식에 `eatout`(외식 기준 단가) 추가.
- 응답에 `units`(구매단위 표) 포함.
```json
{
  "dishes": [
    {"id":"kimchi_jjigae","name":"김치찌개","img":"kimchi_jjigae.png","emoji":"🥘",
     "eatout":8000,
     "ingredients":[{"name":"배추","kind":"crop","crop":"배추","amount_kg":0.12}, ...]}
  ],
  "units": {"배추":{"unit":"포기","kg":2.5}, ...}
}
```

### 8.2 POST /api/meal
요청(기존 동일):
```json
{ "scenario": {"heat_days":28,"drought_idx":75,...}, "month":8,
  "dishes": ["rice","kimchi_jjigae","baechu_kimchi"] }
```
응답(확장):
```json
{
  "total": {
    "cost":   {"predicted":13573,"baseline":12680,"pct":7},
    "eatout": {"predicted":41250,"baseline":40000,"pct":3}
  },
  "dishes": [
    {"id":"kimchi_jjigae","name":"김치찌개",
     "cost":{"predicted":4400,"baseline":4151,"pct":6},
     "eatout":{"predicted":8249,"baseline":8000,"pct":3},
     "ingredients":[ ...기존 동일... ]}
  ],
  "ingredientTotals": [
    {"crop":"배추","unit":"포기","unitKg":2.5,
     "unitPrice":{"predicted":9625,"baseline":5400,"pct":78},
     "predicted":1155,"baseline":648,"pct":78,
     "usedIn":["김치찌개","배추김치"]}
  ]
}
```

### 8.3 응답 필드 설명
| 필드 | 타입 | 설명 |
|---|---|---|
| total.cost / total.eatout | obj | 밥상 총 원가 / 외식가 (predicted·baseline·pct) |
| dishes[].cost / .eatout | obj | 음식별 원가 / 외식가 |
| ingredientTotals[].unit | str | 구매단위 라벨(포기/개/망/단/포대) |
| ingredientTotals[].unitKg | num | 단위 환산중량(kg) |
| ingredientTotals[].unitPrice | obj | 구매단위 가격(predicted·baseline·pct) |
| ingredientTotals[].predicted/baseline | num | 밥상 내 해당 작물 사용분 원가 |

> ⚠ 호환성: 기존 `total.predicted`(평면)에서 `total.cost.predicted`(중첩)로
> 변경된다. 프론트 `renderMeal`도 함께 수정해야 한다(7번 작업).

### 10.2 프론트 수동 QA 체크리스트
1. 밥상 탭 진입 → 음식 드래그/탭 추가 정상.
2. 결과 패널에 **재료 원가·사먹을 때** 두 총액 표시.
3. 음식별 행에 원가·외식가 병기.
4. 원자재 막대에 구매단위 가격(예: 배추 1포기 9,625원) 표시.
5. 프리셋 전환·날씨 공유 시 두 총액 모두 갱신.
6. 빈 밥상 안내, 모바일 폭 레이아웃 정상.
7. 기존 시뮬레이션·퀴즈 탭 회귀 없음.

## 11. 엣지 케이스 / 예외 처리
- 빈 밥상: cost/eatout 0, pct 0.
- 평년 시나리오: 두 pct ≈ 0(전가분 0).
- 풍작(가격 하락): 외식 전가분 음수 허용 → 외식가가 메뉴가보다 소폭 하락.
- 알 수 없는 음식 id: 무시(기존과 동일).
- 분량 0/정가 0 방어, 0 나눗셈 방어(pct).

## 13. 튜닝 포인트 / 오픈 이슈
1. **외식 단가 값**(6.2 표) — 가게 기준에 맞춰 조정 가능.
2. **외식가 전가 방식** — "재료 상승분 전액 가산" 채택. 대안: 배수(원가×3),
   부분 전가(상승분×k).
3. **구매단위·환산중량** — 기존 UNIT_PACK과 동일(쌀은 20kg 포대로 lumpy).
4. **호환성** — 응답 평면 키 → 중첩 키 변경에 따른 프론트 동시 수정 필요.
